# Автотесты API

Проект содержит автоматизированные тесты микросервиса пользователей, объявлений и статистики.

## Технологии

- Java 17
- Maven 3.9+
- JUnit 5
- REST Assured
- Allure Framework
- AspectJ

## Покрываемые API

- `POST /api/1/register`
- `POST /api/1/autorize`
- `POST /api/1/item`
- `GET /api/1/item/{id}`
- `GET /api/1/{sellerID}/item`
- `GET /api/1/statistic/{id}`
- `GET /api/2/statistic/{id}`
- `DELETE /api/2/item/{id}`

## Особенности реализации

- Каждый тест, которому нужны защищённые ресурсы, создаёт отдельного пользователя.
- Имена пользователей и объявлений генерируются динамически с UUID.
- Bearer-токен всегда получается через `POST /api/1/autorize`.
- Тесты не зависят от порядка запуска и данных других пользователей.
- Созданные объявления регистрируются в тестовой сессии и удаляются в `@AfterEach`.
- Уже удалённое самим тестом объявление считается успешно очищенным.
- REST Assured добавляет запросы и ответы в Allure-результаты.
- Пароли и токены не записаны в исходный код как постоянные секреты.

Пользователей удалить невозможно, поскольку соответствующая API-ручка отсутствует.

## Настройка окружения

По умолчанию используется стенд:
https://qa-internship.avito.com

Настройки можно передать системными свойствами Maven:

- `baseUrl` — адрес тестируемого сервиса;
- `connectTimeoutMs` — тайм-аут установления соединения, по умолчанию 5000 мс;
- `socketTimeoutMs` — тайм-аут получения ответа, по умолчанию 10000 мс;
- `performanceMaxMs` — допустимое время ответа для нефункциональной проверки, по умолчанию 5000 мс.

Аналогичные переменные окружения:

- `BASE_URL`;
- `CONNECT_TIMEOUT_MS`;
- `SOCKET_TIMEOUT_MS`;
- `PERFORMANCE_MAX_MS`.

Пример:

mvn clean test \
-DbaseUrl=https://qa-internship.avito.com \
-DperformanceMaxMs=5000

## Запуск всех тестов
mvn clean test

## Запуск отдельного класса
mvn test -Dtest=RegistrationAuthorizationTest

mvn test -Dtest=AccessControlTest

mvn test -Dtest=ItemApiTest

mvn test -Dtest=E2eTest

## Запуск отдельного теста

mvn test -Dtest=E2eTest#userCanCompleteFullAdvertisementLifecycle

### После запуска тестов результаты находятся в каталоге:

target/allure-results

### Сформировать и открыть временный отчёт:

mvn allure:serve

### Сформировать статический отчёт:

mvn allure:report

### Статический отчёт будет создан в:

target/site/allure-maven-plugin


### В отчёте доступны:


- suites и тест-кейсы JUnit;

- Allure epic, feature, story и severity;

- шаги регистрации, авторизации и работы с объявлениями;

- HTTP-запросы и ответы REST Assured;

- сообщения упавших assert-проверок.


## Интерпретация результатов

Тест должен завершаться успешно только при выполнении ожидаемого контракта.

Если тест упал:

1. Открыть Allure-отчёт.

2. Проверить assertion message.

3. Изучить приложенные HTTP-запрос и ответ.

4. Повторить сценарий отдельно, чтобы исключить кратковременный сбой общего стенда.

5. Если расхождение воспроизводится, создать `BUGS.md` и связать дефект с идентификатором тест-кейса из `TESTCASES.md`.

Коды `500` не принимаются тестами как допустимый результат пользовательской ошибки.
